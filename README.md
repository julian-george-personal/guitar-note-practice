# Fretboarder

Guitar note practice tool. Listens to microphone input, detects the pitch you play, and prompts you to hit target notes. Available as a web app and iOS app.

## How it works

On start, the app requests microphone access and runs a Web Audio pipeline: `MediaStream → Compressor → Gain → Analyser`. A `requestAnimationFrame` loop reads the analyser buffer ~60fps, runs YIN pitch detection (`pitchfinder`), and emits `AudioData` (`note`, `freq`, `db`) into the active exercise on every frame.

Each exercise receives `AudioData` as a prop, picks a target note, and uses `useNoteMatch` to compare detected vs. target. When the correct note is held for 200ms, `useNoteMatch` triggers a 400ms "correct" flash and the exercise advances.

## Exercises

- **Note** — random notes, optionally filtered to a scale
- **String** — random notes filtered to a specific string's range, given a tuning and fret range
- **Custom (AI)** — user describes an exercise in plain text; a Lambda calls AWS Bedrock (Claude Haiku) and returns an `ExerciseConfig` JSON that drives the session

## Structure

```
├── web/           # React/Vite web app
│   ├── src/
│   │   ├── exercises/   # one component per exercise mode plus the shared frame wrapper
│   │   ├── components/  # reusable UI: note displays, fretboard diagram, volume bar, config inputs
│   │   ├── hooks/       # custom hooks for note matching, validated text inputs, and debug mode
│   │   └── lib/         # audio pipeline, pitch detection, exercise config schema, string/fret math
│   └── public/      # static assets
│
├── job/           # Typescript job for prompting AWS Bedrock to generate exercises
├── ci_scripts/    # Xcode Cloud build scripts (required directory name)
└── .github/       # GitHub Actions CI/CD
```

## Deploy

Push to `main` triggers the GitHub Actions workflow, which builds the web app and deploys it to S3. The Lambda is also built and deployed to AWS in the same workflow.

iOS builds are handled by Xcode Cloud, which triggers on push to `main`, runs `ci_post_clone.sh`, and uploads the result to TestFlight.

## iOS

The web app is wrapped with Capacitor. The `ios/` directory is gitignored — it is fully regenerated by `ci_scripts/ci_post_clone.sh` on Xcode Cloud and locally via:

```bash
npm run ios:init   # first time setup after cloning
npm run cap:build  # rebuild web + sync to ios/ (ongoing)
npm run cap:open   # open Xcode
```

iOS-specific concerns are kept out of the web source:
- Safe area CSS uses `env(safe-area-inset-*)`, which resolves to `0` on desktop
- iOS meta tags (`apple-mobile-web-app-*`) are injected at build time by a Vite plugin only when `CAPACITOR=true`
- Microphone permission string lives in `capacitor.config.ts` (`ios.infoPlist`)

## Local dev

```bash
npm install
npm run dev      # web dev server + local Lambda test server
npm run build    # production web build
npm run lint
```
